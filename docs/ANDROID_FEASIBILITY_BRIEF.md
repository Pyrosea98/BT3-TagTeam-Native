# Android feasibility spike (Claude brief for Codex, 2026-10-08)

Question: can the native runtime run BT3 + Tag Team on Android ARM64 (and x64 devices) at playable speed? Answer with measurements, not guesses. Builds on `INSTALLER_PLAN.md` (Android specifics and the input plan).

1. **Toolchain:** can `ps2xRuntime` build for `aarch64-linux-android` with the NDK (CMake, Clang)? List the blockers: Windows-only code (Win32, WASAPI, named pipes), threads and fibers (`PS2X_FIBERS`), SDL2 on Android, file access through the Storage Access Framework (see the import plan), and executable-memory limits (we use static recompilation plus an interpreter; no JIT expected).
2. **Rendering:** paraLLEl-GS needs specific Vulkan features (compute, subgroup operations, 8/16-bit storage, possibly more). Probe which Android GPUs support them (Adreno 6xx/7xx/8xx, Mali-G7xx, Immortalis, Xclipse, PowerVR) and produce a required-feature list and a device compatibility table. Evaluate a fallback renderer (OpenGL ES or a Vulkan rasteriser path of the runtime) and its cost.
3. **CPU budget:** on a Ryzen 5700G a 5v5 fight takes about 26-41 ms of guest time (20-30 updates/s) and small matches reach 60. Estimate phone performance: run the headless fight benchmark (the saved-state profile fixtures) on an ARM64 device (mid-range and flagship) and on an x64 Android emulator for correctness. Report updates/s per roster size, memory (128 MiB EE plus VRAM and resources), thermals over 10 minutes, and battery.
4. **Python:** the controller and mod logic still run in embedded Python today and Android cannot ship that casually. List what blocks removing it for Android (see `PYTHON_LEDGER.md`) and a minimal frozen or native subset for a first Android build.
5. **Deliverable:** a short report with a go/no-go per feature (single fight, mod modes, split screen, online), the measured numbers, the unknowns, and the smallest first Android milestone (for example a headless benchmark APK, then a menu-only build, then a playable 1v1). No UI work yet.
