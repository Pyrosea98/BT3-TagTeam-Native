# Review of the upstream Tag Team Mod "Version 11" (tag v0.1.0-beta.11) (Claude, 2026-10-09, read-only)

Sources: the local source checkout `Budokai-Tenkaichi-3-Tag-Team-Mod-PCSX2--0.1.0-beta.11/` (read only, nothing was run) and the GitHub release page https://github.com/tehmufti/Budokai-Tenkaichi-3-Tag-Team-Mod-PCSX2-/releases/tag/v0.1.0-beta.11 (pre-release dated 09 Oct; the asset list did not load).

## What it is
The upstream PCSX2 mod by The Mufti, now with Windows and Linux installers and updaters, regional adapters (BT3 USA, Europe, Japan "Sparking! Meteor", BT4 B14 REV2 English and Spanish) and an **experimental online mode**. The numbering restarted: after 0.1.0-beta.45 it became Version 7, 8, 9, 10 and 11. Our controller base (`experiments/.full-install`) is **0.1.0-beta.32**, so we are about 13 releases behind.

## New things since beta.32 (from `player-installer/CHANGELOG.md`)
Gameplay: Natural and Fighter walking and running styles (Version 11; animation samples adapted from Mannequiny, CC BY 4.0, attribution required); "Allow fusions" switch for humans and CPUs; tournament ring-outs (permanent elimination, a team loses only when everyone is out, takeover of a surviving CPU teammate, can be switched off); beam clash camera option and up to four teammates assisting a beam struggle (beta.41); right-stick target picking and the gold-arrow or ring target indicator (beta.35, beta.39); updated walking/running and safer defusion placement (beta.40); splash damage and tag attacks removed (beta.38); fixes for a 5v5 freeze with several after-image trails and for rush/ultimate pairs frozen about 20 s (beta.37), and the "more than 1,024 patch records" preparation limit (beta.42).
Online (TTM Online 2.1): rooms with a lobby, up to ten humans (5v5), unequal teams, passwords, LAN discovery, optional room directory, spectators, CPU handoff when a player leaves, host-controlled settings, startup caches that shorten online starts, each client shows its own fighter and target HUD. It runs on PCSX2 with deterministic sessions, so the code is not reusable by our native runtime, but the lobby/room design and rules are a good reference.
Tools and content: Workbench (modder GUI), Custom Scenarios and "Modded Scenarios" (story missions), Spanish BT4, a Game disc page, error codes (TTM-...), an updater with recoverable backup.

## How far our code has diverged (measured by file hashes of the `.py` tools)
Base beta.32: 227 files. Ours: 233. Upstream v11: 283. Since our base upstream **changed 172 files and added 56**. Of the changed ones **142 are untouched by us (safe to take)** and **30 were also modified by us (merge by hand)**: autopilot, controller_assignment, controller_mailbox, display_settings, extra_generic_effects, extra_reload_forms/preload/worker, extra_special_pools, feature_preferences, four_player_mode, fresh_team_trainer, fusion_duration(+_worker), fusion_partner_lifecycle, game_profile, guest_killfeed, guest_loading_screen, localization, mod_settings, multi_contact, multiplayer_fusion, native_menu_loading, native_menu_services, native_mode_menu, quad_controller, quad_menu_input, team_assignment, team_start_gate, teammate_revive. Our own native additions are only 6 new files. So a three-way merge (base beta.32, ours, upstream v11) is realistic.
New upstream modules of interest: `tournament_ringout.py`, `beam_struggle.py`, `battle_camera_zoom.py`, `lockon_select.py`, `lockon_threat.py`, `arena_bounds.py`, `aux_trail_lists.py` (the 5v5 freeze fix), `outnumbered.py`, `ground_*` (walking and running styles), `story_*` and `mission100.py` (scenarios). PCSX2-only ones (`process_identity.py`, `controller_checkin.py`, `controller_hub.py`, `disc_library.py`, `disc_page.py`, the Workbench GUI) are not needed natively.

## Risks of merging
The new hooks were written for PCSX2 and the stock USA executable; our target is the Power Scale executable running natively, so each new guest hook needs the same "reviewed owner/guard" treatment as the existing ones (see `game_profile.py`), and the native-only features (overhead HUD, CPU tactics, four-seat pads, installer) must keep working. New features should ship default Off until live-tested.

## Licence and repositories (important)
- Upstream is **GPL-3.0-only** (LICENSE, NOTICE: "Tag Team Mod contributors"). Its CONTRIBUTING says changes should be made **in a fork** and that a modified build must change the version.
- Our native runtime is a checkout of **github.com/z3xox/BT3-Recomp** (our `native-port/repo`, 68 locally modified files, no remote of ours), also **GPL-3.0**.
- We distribute a combined work (the runtime plus the embedded controller derived from the mod). Under GPLv3 that means: ship the licence texts and NOTICE/attribution, mark our changes, and **offer the corresponding source** with every installer. Publishing our own public repositories under GPL-3.0 is the simplest compliant route, and it also makes the project eligible for **free code signing from SignPath Foundation** (OSI licence + public repo).
- Recommended layout: (1) a fork of the mod repo for the Python/guest side (keeps `upstream` as a remote for future merges); (2) a fork of BT3-Recomp for the native runtime, UI, installer and docs. Never commit the game: `power-scale-input/` (ELF, MOD.BIN, DLC.AFS), ISOs, saves, captures, logs, `repo/build` (7 GB), the derived import data or any Sony/Bandai asset. Keep the name distinct from "Tag Team Mod" (for example "BT3 Tag Team Native") and keep the credits (Power Scale: LetsPlayBt3; Tag Team: The Mufti; RidJuampa). Courtesy: tell The Mufti before publishing.
